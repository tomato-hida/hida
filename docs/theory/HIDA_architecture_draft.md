## Abstract

HIDA（Human-Inspired Dynamic Architecture）は、身体（L1）、クオリア（L2）、世界モデル（L3）、記憶（L4）の四つの処理層からなる認知アーキテクチャである。全体を調整する司令塔を持たない。クオリア・世界モデル・記憶の三層のうち、その層のいつもの水準から最も盛り上がった層が主導層となり、他の層が追随層として応答する。身体（L1）は信号を渡す側で、主導はしない。主導層は固定されず、状況に応じて入れ替わる。

本アーキテクチャは、層どうしの同期状態を二つの量で記述する。同期の強さ（sync_score）と、どの層が主導しているか（sync_type）である。sync_score は、主導強度と追随整合性の幾何平均として算出する。さらに、主導層が追随層の更新ゲインを引き上げる引き込み機構を実装し、主導から追随への時間的な因果を力学として持たせた。

実装は Python の標準ライブラリのみで動作する。引き込み機構の有無を比べたアブレーション検証（30シード）では、主導イベント直後の追随層の応答が、30シード中25シードで引き込みありの方が大きかった（符号検定、両側 p ≈ 0.0003）。ただし効果量は小さく、時間遅れ相関はゼロ付近にとどまる。また、測定した量は引き込みゲインが直接掛かる量そのものである。

続く測定で、v2.1 の主導層の決め方（活動量が最大の層）では、層ごとの目盛りの違いで主導層が決まっていることが分かった。身体層は一度も主導せず、地図を与えない条件では記憶層だけが主導した。決め方を「いつもの水準からの盛り上がり」に変えた実験実装では、三層のあいだで主導が入れ替わり、引き込みありの条件で主導層の交代が増えた（地図なしの二条件で、符号検定 両側 p ≈ 0.002 と 0.001）。主導強度と次のステップの追随層の活動のあいだの相関も、時刻を入れ替えた対照より高くなった。行動が良くなることは確認していない。

あわせて、行動の決定をアーキテクチャ側に置き、LLM を説明役だけに使う構成での観察を報告する。目標達成後の待機96ステップのすべてで、LLM は待機に目的があるかのような説明を生成した。

**Keywords:** cognitive architecture, leader-follower synchronization, entrainment, embodied agent, predictive processing, ablation study, confabulation, HIDA

## 1. はじめに

人間の認知では、処理の中心が状況に応じて移る。指を切った瞬間は痛みが前に出る。問題を解いているときは予測と推論が、昔のことを思い出しているときは記憶が前に出る。本研究は、この移り変わりを、司令塔を置かずに実現するアーキテクチャを作ることを目的とする。

複数の機能を連携させる認知アーキテクチャの多くは、次にどの機能を使うかを決める調整役を持つ。HIDA はそれを持たない。四つの層が互いに情報を送り、受け取る中で、最も活動している層が結果として主導する。本研究が扱う問いは「誰が次の処理を指示するのか」ではなく、「なぜ、その層が次に主導する状態になったのか」である。

本文書は、アーキテクチャの仕様、実装、検証を述べる。設計の前提（意識の問いに対する立場、クオリアの扱いなど）は、別文書「HIDA の理論的前提」に分けた。本文書では、層どうしの同期を「意識」とは呼ばず、「同期状態」と呼ぶ。

本文書の元になったのは HIDA v2.1 論文である。v2.1 では意識の理論とアーキテクチャの記述が一つの文書に混ざっていた。本文書は、そのうちアーキテクチャにあたる部分を整理し直したものである。節番号は付け直してある。

**本文書の内容：**

1. 四つの層と、主導・追随による同期状態の定義（§3）
2. 同期スコアの算出と引き込み機構の実装（§4）
3. 引き込み機構のアブレーション検証、self_strength の実測、LLM を説明役にした構成での観察（§5）
4. 実装で検証できる予測（§6）

## 2. 関連研究

認知アーキテクチャは、知覚・記憶・判断・行動を一つの固定した枠組みで扱う設計を指す。Newell（1990）は、アーキテクチャそのものを認知の統一理論として扱う立場を示した。これまでに多数のアーキテクチャが提案されている（Kotseruba & Tsotsos, 2020）。ここでは、「次の処理を誰が決めるか」という点で HIDA と比べる。

| アーキテクチャ | 次の処理を決める仕組み |
|---|---|
| Soar（Laird, 2012） | 決定サイクルが、候補の中から一つのオペレータを選ぶ |
| ACT-R（Anderson et al., 2004） | 手続きモジュールが、各サイクルで発火させるプロダクションを一つ選ぶ |
| LIDA（Franklin et al., 2014） | 注意を引く内容どうしが競合し、勝った内容が全体に放送される（グローバル・ワークスペース理論の実装） |
| 包摂アーキテクチャ（Brooks, 1986） | 中央のモデルを持たない。行動の層を重ね、上の層が下の層の出力を抑制する |
| MAP（Webb et al., 2025） | 競合の監視、状態の予測、状態の評価、課題の分解などを別々のモジュールにし、調整も専用のモジュールが担う。各モジュールは LLM で作られている |
| **HIDA** | 選ぶ部品を持たない。各時点で、いつもの水準から最も盛り上がった層が主導層になる |

Soar、ACT-R、LIDA、MAP は、選択や調整を担う部品を持つ。包摂アーキテクチャは中央の部品を持たない点で HIDA に近いが、層の優先順位は設計時に固定されている。HIDA では、どの層が前に出るかは各時点の活動量で決まり、固定されない。

LIDA との違いは、放送のための場の有無である。LIDA には、競合に勝った内容が入る共有の場がある。HIDA にはその場がなく、主導層が追随層の応答を直接増幅する（§4.9）。

L3 の予測と誤差の扱いは、予測処理の枠組み（Friston, 2010）と対応する。

## 3. アーキテクチャ

### 3.1 四つの層と閉じたループ

```
第1層：身体（Body）          ── 環境と身体内部の変化の検出
                               外受容（皮膚・目・耳など）と
                               内受容（ホルモン・自律神経・疲労・体温・血糖など）
第2層：クオリア（Qualia）     ── 高速な分類と価値づけ（DNA初期値＋学習値）
第3層：世界モデル（World Model）── 状況の構造化と予測
第4層：記憶（Memory）         ── 過去との照合、自己モデルの形成
──────────────────────────────────────────────
第5層：同期状態              ── L1〜L4 の主導・追随の同期を記述する量（処理層ではない）
```

情報は閉じたループを流れる。

```
環境 → L1 → L2 → L3 → L4 → 行動 → 環境
        ↑________________________________|
```

L1〜L4 に序列はない。番号は処理の説明のための名前である。主導層になりうるのは L2・L3・L4 で、L1 は主導しない（§3.2）。

### 3.2 各層の役割

#### 第1層：身体

環境と身体内部の変化を信号として検出する。主導・追随の枠組みの中で、L1 は三つの役割を持つ。

- **センサー：** 外受容と内受容を通じて変化を捉える。
- **L2 への入力：** 痛覚、温度の急変、姿勢の崩れ、ホルモンの変動などは、L1 から L2 に渡される。それを受けて痛みや不快として前に出るのは L2 である。L1 自身は主導層にならない。
- **現実接地の担い手：** L1 の外受容入力は、L3 の予測と L4 の想起に「今、ここで起きていること」を供給し続ける（§3.3 定義7）。

| 入力 | 主な機能 |
|---|---|
| 外受容 | 現実接地、L2 への入力 |
| 内受容 | 持続的な身体状態、L2 への入力 |

> **草稿 0.2 での変更：** 0.1 と v2.1 論文では、L1 を「同期信号の発生源」とし、指を切った瞬間を L1 主導の典型としていた。0.2 ではこれを改め、L1 は信号を渡す側、主導するのは L2 以降とした。組織が傷ついたという信号（侵害受容）と、痛いという体験とを分ける区別に対応する。

身体の状態が、特定の層を通さずに全体に効く場合がある。眠気、発熱、低血糖、麻酔などである。これらは一つの層が盛り上がって他を引き込む形ではなく、全部の層の感度が一度に上下する形をとる。主導・追随とは別の経路として扱う。この経路（覚醒度による全体のゲイン）は hida_v2_1/hida_v21_work.py に試作があるが、検証していない。

L1 は追随層としては他の層と同じに扱う。引き込みゲインを受け、追随整合性にも数える。

現行の実装では、L1 の活動量はエネルギーと疲労の変化量から計算する（§4.2）。外受容由来と内受容由来を分けて測ることは、今後の拡張である。

#### 第2層：クオリア

信号を高速に分類し、価値づけする。各クオリアは生まれつきの初期値を持ち、経験によって更新される。

```
最終的な価値 = DNA初期値 + 学習値

例：コーヒーの苦味
  DNA初期値: -0.6（苦い→避ける）
  学習値:    +0.8（覚醒感・社会的報酬）
  最終値:    +0.2（好き）
```

クオリアは「何の信号か」の分類（物理的クオリア）と「どれくらい重要か」の判定（感情的クオリア）に使われる。この二つは素材が同じで、処理上の役割が違う（理論的前提 §4.2）。

#### 第3層：世界モデル

L2 の出力を受けて、状況を構造化する。どこで起きているか、どれくらいの強さか、何が原因か、放置すると危険か、どう対処するか、次に何が起こるか、を扱う。予測と実際の差（予測誤差）が、L3 の活動量の主な成分になる。

#### 第4層：記憶

現在のパターンを過去のパターンと照合する。記憶は保存された過去そのものではなく、呼び出すたびに現在の状態に合わせて再構成されるものとして扱う。

照合の繰り返しによって積み上がる量を self_strength と呼ぶ。実装では、1ステップごとに「直近10個の入力のうち隣り合って同じだった組の数（0〜9）」に係数 k を掛けた値を加算し、1.0 を上限とする。減衰はない。

> **実装の現状：** self_strength は experiments/02_phases/ の Phase 1〜5 に実装されている。現行の本体（hida_v2_1/）には実装されていない。実測値は §5.2 に示す。

#### 第5層：同期状態

第5層は処理層ではない。行動を選択する主体でも、L1〜L4 を維持・制御する主体でもない。L1〜L4 が主導・追随の関係を通じて同期したとき、その状態を記述するための量である。

> **コード上の名前：** 実装では、この記述を行うクラスを `L5Consciousness`、同期ONの判定結果を `is_conscious` と呼んでいる。v2.1 までの名前を引き継いだもので、本文書ではそれぞれ「同期判定」「同期ON」と読む。同期状態を意識と呼ぶかどうかは、理論的前提 §7 で扱う。

### 3.3 主導・追随の定義

**定義1：同期信号**  
ある層の活動量が閾値を超え、他層の状態更新を誘導する起点となる信号。

**定義2：活動量**  
層ごとに測定される、状態の変化の強さ。

- L1：身体状態の変化量
- L2：価値の変化量（valence・arousal・qualia の変動）
- L3：予測誤差の増分
- L4：記憶再活性化の増分

活動量は状態の大きさではなく、「その層が今、同期信号を出しているか」を表す。層ごとに質の違う量なので、正規化して比べる。

**定義3：主導層**  
L2・L3・L4 のうち、その時点で、その層のいつもの水準からの盛り上がりが最大の層。盛り上がりが閾値に届く層がなければ、主導層はない。  
（0.1 では「その時点で最大の活動量を示す層」としていた。v2.1 の本体はこの旧い決め方で動いている。変更の理由は §5.5、計算は §4.13。）

**定義4：追随層**  
主導層以外の3層。主導層の活動に応じて状態が変化する。

**定義5：同期**  
主導層の活動に対して、追随層が一定時間内に整合的に変化すること。

**定義6：同期状態（第5層）**  
主導層が同期信号を発し、追随層が整合的に応答することで成立する動的な状態。持続する実体ではなく、瞬間ごとに成立・消滅する同期イベントの連続である。

**定義7：現実接地**  
L1 の外受容入力が、L3・L4 の内部生成を継続的に修正している状態。

### 3.4 主導層は入れ替わる

主導層は固定されない。入力と内部状態に応じて、その時々で違う層が主導する。

| 状況 | 同期信号の発生源 | 追随の例 |
|---|---|---|
| 手を切る | L2（痛み。L1 の信号がきっかけ） | L1（心拍、筋の緊張）、L3（認識）、L4（対処の記憶） |
| 数式を解く | L3（推論） | L4（公式の想起）、L2（解への期待）、L1（姿勢） |
| 突然の怒り | L2（情動） | L1（心拍）、L3（理由探し）、L4（過去の類似感情） |
| 既視感 | L4（記憶照合） | L2（懐かしさ）、L3（記憶の特定）、L1（軽い身体反応） |

一つの出来事の中でも、主導層は移る。指を切ったときの数秒間を、主導層の移り変わりとして書くと次のようになる。

| 段階 | 起きること | 主導層 |
|---|---|---|
| 1 | 「痛い！」 | L2（痛み。L1 の信号がきっかけ） |
| 2 | 「これはどれくらいまずいのか」 | L2（価値づけ） |
| 3 | 「どうしよう」 | L3（予測・計画） |
| 4 | 「前にこういう傷はどうしたか」 | L4（記憶） |
| 5 | 「絆創膏で済むか、救急車か」 | L3（予測・計画） |
| 6 | 絆創膏を探す | L4 と L3 が交代（記憶と確認の繰り返し） |

L3 は段階3と段階5に現れる。段階3では対処の枠組みを起動し、そのために L4 が引き出される。段階5では、引き出された記憶を使って判断する。主導層の移動は各層を一度ずつ通る一方向の流れではなく、必要に応じて前の層へ戻る過程である。

段階6の「探す」は、どこに置いたかを思い出すこと（L4）と、そこにあるかを確かめること（L3）の繰り返しである。L4 と L3 が交代で主導し、体（L1）は追随して動く。0.1 ではこの段階を L1 主導としていた。

> **実装の現状：** この表は設計が目標とする動きを示した概念例であり、現行の実装がこの順番を再現したわけではない。主導層が入れ替わる経路の実装状況は §3.6 に述べる。

### 3.5 同期状態の二軸

同期状態は二つの量で記述する。

**1. 同期スコア（強さの軸）**

```
sync_score = √(leader_strength × follower_coherence)
```

leader_strength は主導層の活動量、follower_coherence は追随層の整合的な応答の度合いである。[0, 1] に正規化する。幾何平均なので、どちらか一方だけが高くてもスコアは上がらない。主導層が暴走しているだけでは同期にならない。

**2. 主導タイプ（どの層が主導しているかの軸）**

```
sync_type ∈ {L2主導, L3主導, L4主導}
```

複数の層の活動量が近く、はっきりした主導層が前に出ない状態を、均衡的同期状態と呼ぶ。

> **離散化の限界：** sync_type は「最大活動量を持つ一つの層」として離散的に定義している。実装と検証ができる最小の形としてこれを選んだ。実際には複数の層が同程度に関与する混合状態がありうるので、各層が主導性をどの程度分け持つかの連続分布として記述する拡張が考えられる。

### 3.6 司令塔を置かない

HIDA には、次にどの層を使うかを決める部品がない。主導層の特定（§4.3）は、各層の活動量の最大値を取る計算であり、層に指示を出すものではない。

設計が目標とする動きは次のとおりである。L3 が作った予測が L4 に届き、L4 で記憶との照合が活発になる。その活動が他の層を引き込むほど大きくなれば、L4 が主導する。照合の結果が L3 に戻り、予測の修正が活発になれば、主導は L3 に戻る。各層が自分の役割を果たす中で、結果として主導が入れ替わる。

現行の実装で、同期判定が各層の動きに作用する経路は一つだけである。主導層が特定されると、次のステップで追随層の更新ゲインが引き上げられる（引き込み機構、§4.9）。同期ONの判定は言語化を行うかどうかの条件に使われ、行動の選択には使われない。

> **実装の現状：** 現行の実装では、主導層の交代は、各層の活動量が上下した結果として起きている。「情報を受け取った層の活動量が、受け取ったことによって上がる」という経路は、まだ実装されていない。引き込み機構は追随層の応答を増幅するものであり、主導層の交代そのものを生む力学ではない。この経路の実装は、本アーキテクチャの最初の課題である（§8）。

## 4. 実装

### 4.1 概要

実装は Python の標準ライブラリのみで動作し、外部ライブラリを必要としない。LLM は言語化のための部品として切り離してあり、接続しなくても動作する。

```python
class MinimalConsciousness:        # v2.1 までの名前を引き継いでいる

        self.l2 = L2Qualia()       # クオリア
```

§4.2〜§4.9 は v2.1 の本体（hida_unified_v2.py）の記述である。草稿 0.2 で変えた主導層の決め方と閾値は、§4.13 に分けて述べる。§4.3（主導層の特定）と §4.6 の閾値は、§4.13 で置き換わる。

### 4.2 活動量の測定

各層の活動量は、**前ステップからの状態変化の強さ**として定義される。状態の絶対値ではなく、変化量を用いる理由は、第5層が「**ある層が今、同期信号を出しているか**」を判定するための量であるためである。

```python
def measure_activity(self, l1, l2, l3, l4):
    """各層の活動量を変化量として測定"""
    # L1: 身体状態の変化量
    l1_change = abs(l1.energy - self.prev.l1_energy) + \
                abs(l1.fatigue - self.prev.l1_fatigue)
    l1_act = clip01(l1_change / 1.0)
    
    # L2: 価値変化量（valence/arousal/qualiaの変動）
    l2_change = abs(l2.valence - self.prev.l2_valence) + \
                abs(l2.arousal - self.prev.l2_arousal) + \
                sum(abs(l2.qualia[k] - self.prev.l2_qualia.get(k, 0)) 
                    for k in l2.qualia)
    l2_act = clip01(l2_change / 3.0)
    
    # L3: 予測誤差イベント数または誤差強度の増分
    l3_change = max(0, l3.error_count - self.prev.l3_error_count)
    l3_act = clip01(l3_change / 3.0)
    
    # L4: 記憶再活性化の増分（初期実装の代理指標）
    l4_change = max(0, l4.activation_count - self.prev.l4_activation_count)
    l4_act = clip01(l4_change / 3.0)
    
    return {'L1': l1_act, 'L2': l2_act, 'L3': l3_act, 'L4': l4_act}
```

各層の正規化定数（1.0, 3.0, 3.0, 3.0）は、その層の典型的な変化量を1ステップあたりで [0, 1] に収めるためのスケーリング係数である。これらは実装時の経験的調整値であり、対象ドメインに応じて調整される。

**代理指標についての注記**：

ここで示す活動量計算は初期実装のための代理指標である。特に**L4活動量**については、現行コードでは発見物数や記憶追加の増分を用いるが、理論上のL4活動量は以下を含む：

- 新規記憶の追加
- 既存記憶とのパターン照合強度
- 長期記憶の再活性化
- 自己履歴参照の強度
- 感情原因の想起

これらすべてがL4活動量に寄与する。現行の単純な実装は、夢・既視感・フラッシュバック・復讐動機などのL4主導現象を完全には表現しきれない。

したがって、**v2.0の中核は特定の代理指標ではなく、「どの層が同期信号を発し、他層がどの程度追随したか」を記述する構造にある**。代理指標は実装の便宜であり、設計はより広い活動量定義を許容する。

### 4.3 主導層の特定

主導層は、活動量が閾値を超える層のうち、最大値を持つ層として特定される。閾値を超える層が存在しない場合、主導層は定まらず、第5層の同期は成立しない。

```python
LEADER_THRESHOLD = 0.3

def detect_leader(self, activities):
    """主導層の特定：閾値超過層のうち最大活動量を持つ層"""
    candidates = {k: v for k, v in activities.items() 
                  if v >= LEADER_THRESHOLD}
    
    if not candidates:
        return None, 0.0  # 同期信号なし
    
    leader = max(candidates, key=candidates.get)
    return leader, candidates[leader]
```

閾値 `LEADER_THRESHOLD = 0.3` は、層が「同期信号を発した」と判定する境界値である。これより低い活動はノイズ的揺らぎとして扱われ、主導層とはみなされない。

なお、複数層の活動量が近い場合、最大活動量を持つ層が主導層となるが、この場合の同期は§3.5で述べた「**均衡的同期状態**」に近くなる。明確な主導層が前景化しない状態である。

将来的には、最大活動量だけでなく、新奇性 (novelty)、緊急度 (urgency)、記憶再活性化の独立性などを組み合わせた多軸判定への拡張も可能である。

### 4.4 追随整合性の評価

主導層が特定された後、他3層が主導層に対してどの程度整合的に応答しているかを測定する。

**v2.0実装の問題（約分問題）**

v2.0初期実装では、追随層の活動量平均を主導層の活動量で正規化する簡易的な同時応答指標を用いていた：

```python
# v2.0（問題のあった実装）
coherence = clip01(follower_mean / leader_strength)
sync_score = leader_strength * coherence
```

しかし主導層は定義上「全層の最大活動量を持つ層」であるため、常に `follower_mean <= leader_strength` が成立する。このとき `coherence = follower_mean / leader_strength` となり、これを `sync_score = leader_strength × coherence` に代入すると `leader_strength` が**約分されて消え**、`sync_score = follower_mean`（追随層活動量の平均）と厳密に一致してしまう。すなわちv2.0の「主導強度 × 追随整合性」は、実質的に**追随層3層の活動量平均**でしかなく、主導強度はスコアに一切寄与していなかった。さらに重要なことに、この指標は**同時刻の活動量しか見ておらず**、主導層の活動が先行し追随層が後続して応答したという「主導→追随」の時間的因果を区別できない。「たまたま同時に活発化した」状態と「主導に引き込まれた」状態が同じスコアになる。

これはv2.0の存在意義に直結する問題である。非対称性こそがv1.1を超えた点なのに、その非対称性が測れていなかった。

**v2.1実装：絶対量＋時間遅れ応答の合成**

v2.1では追随整合性を二成分の合成として再定義する。第一に、同時応答成分を主導強度で正規化せず**絶対量**のまま用いる（約分問題の解消）。第二に、前ステップの主導信号に対する追随層の活動上昇を測る**時間遅れ応答成分**を導入する。

```python
def measure_follower_coherence(self, activities, leader, leader_strength):
    """追随整合性（v2.1：同時応答＋時間遅れ応答）"""
    # 成分1: 同時応答（絶対量。主導強度で正規化しない）
    follower_mean = sum(v for k, v in activities.items()
                        if k != leader) / 3.0

    # 成分2: 時間遅れ応答
    # 前ステップに主導信号があれば、その追随層が今ステップで
    # どれだけ活動を上昇させたかを、前ステップ主導強度に対する比で測る
    if self._prev_leader is not None and self._prev_leader_strength > 0:
        prev_followers = [k for k in activities if k != self._prev_leader]
        rise = sum(max(0.0, activities[k] - self._prev_activities[k])
                   for k in prev_followers) / 3.0
        lag_response = clip01(rise / self._prev_leader_strength)
        coherence = (1 - LAG_WEIGHT) * follower_mean + LAG_WEIGHT * lag_response
    else:
        coherence = follower_mean

    return clip01(coherence)
```

`LAG_WEIGHT = 0.5` は同時応答成分と時間遅れ応答成分の重みである。時間遅れ応答が「主導→追随」の時間的因果を捉える鍵となる成分であり、この成分が機能するのは、§4.9で導入する**引き込み機構**によって主導層が実際に追随層を駆動する力学が実装されているからである。引き込み機構なしには、時間遅れ応答は単なる偶発的な共変動の測定にとどまる。

なお、`leader_strength` が `LEADER_THRESHOLD = 0.3` 以上に限定されているため、主導層が極めて弱い状態で偽の高coherenceが発生する事態は抑制されている。

**位相同期・結合強度への発展余地**

時間遅れ応答は、主導から追随への時間的因果を捉える最初の操作的指標である。より厳密には、**位相同期 (Phase Locking Value)**、**伝達エントロピー (transfer entropy)**、**結合強度 (coupling strength)** のような方向性を持つ指標への拡張が考えられる。v2.1の時間遅れ応答はその最小実装であり、§5.1のアブレーション検証はこの実装が実際に因果チャネルとして機能していることを示す。一方、その定量的強度（相関としての検出力）にはまだ限界があり、より感度の高い指標への置き換えはv2.2以降の課題である。

### 4.5 同期スコアの算出

同期スコアは、主導強度と追随整合性の**幾何平均**として定義される：

```
sync_score = √(leader_strength × follower_coherence)
```

§4.4で追随整合性を絶対量＋時間遅れ応答として再定義したことで、`leader_strength` はもはや約分されず、主導強度と追随整合性が独立にスコアへ寄与する。幾何平均を採るのは、積（v2.0）と比べて値域が直感的であり、かつ「どちらか一方だけが高くてもスコアは上がらない」性質を保つためである。これにより、以下が表現される：

- **主導強度が低い** → 同期信号自体が弱い → スコア低
- **追随整合性が低い** → 主導層が孤立、他層が応答していない → スコア低
- **両者が高い** → 主導層が強く発火し、他層が整合的に応答 → スコア高

主導強度のみで判定した場合（v1.1的）、ある層だけが暴走しているケースでも高スコアになる。幾何平均で追随整合性を組み合わせることで、**「主導と追随の関係が成立しているか」**が判定される。片方がゼロならスコアもゼロになり、「主導層の暴走だけでは同期にならない」という意図が保持される。

### 4.6 時間的平滑化とヒステリシス

瞬間ごとの sync_score は揺らぐため、時間方向の平滑化と判定の安定化を行う。

```python
EMA_ALPHA = 0.35
ON_THRESHOLD = 0.08   # v2.1で再較正
OFF_THRESHOLD = 0.05  # v2.1で再較正

def smooth_and_judge(self, raw_sync):
    """EMA平滑化とヒステリシス付き判定"""
    self.ema = (1 - EMA_ALPHA) * self.ema + EMA_ALPHA * raw_sync
    
    if not self.is_conscious:
        self.is_conscious = (self.ema >= ON_THRESHOLD)
    else:
        self.is_conscious = (self.ema >= OFF_THRESHOLD)
    
    return self.is_conscious
```

- **EMA (指数移動平均)**：α=0.35 により、過去の状態を保持しつつ、新しい変化に応答する
- **ヒステリシス**：同期ONになる閾値 (0.08) と OFFになる閾値 (0.05) を分離することで、境界付近での点滅を抑制する

> **v2.1注記（閾値の再較正）：** v2.0では ON/OFF 閾値を 0.55/0.50 としていたが、これはより大きな変化量スケールを前提とした概念値であった。v2.1で sync_score を幾何平均に改めたことで実際の値域が変わったため、ON/OFF を 0.08/0.05 に再較正した。較正基準は「同一シナリオで v2.0 と同等の同期ON頻度を維持すること」とした。EMA係数とヒステリシスの機構そのものはv1.1から継続採用しており、実装上の安定性が確認されている。正規化定数と閾値の整合的な調整はコミュニティ検証に開かれている。

### 4.7 統合：check_sync 関数

以上の処理を統合した同期判定関数を以下に示す：

```python
def check_sync(self, l1, l2, l3, l4):
    """第5層の同期判定（v2.1：主導・追随モデル＋引き込み）"""
    
    # Step 1: 各層の活動量を測定（変化量として）
    activities = self.measure_activity(l1, l2, l3, l4)
    
    # Step 2: 主導層の特定
    leader, leader_strength = self.detect_leader(activities)
    
    if leader is None:
        raw_sync = 0.0
        self.sync_type = None
    else:
        # Step 3: 追随整合性の評価（同時＋時間遅れ）
        follower_coherence = self.measure_follower_coherence(
            activities, leader, leader_strength
        )
        # Step 4: 同期スコアの算出（幾何平均）
        raw_sync = sqrt(leader_strength * follower_coherence)
        self.sync_type = leader
    
    # Step 5: EMA平滑化とヒステリシス
    self.ema = (1 - EMA_ALPHA) * self.ema + EMA_ALPHA * raw_sync
    self.sync_score = self.ema
    if not self.is_conscious:
        self.is_conscious = (self.ema >= ON_THRESHOLD)
    else:
        self.is_conscious = (self.ema >= OFF_THRESHOLD)
    
    # Step 6: 引き込みゲインの計算（次ステップの力学に作用）
    # 主導層は追随層の更新ゲインを 1 + ENTRAIN_K × 主導強度 に引き上げる。
    # 主導層自身のゲインは1.0（自分で自分を引き込まない）。
    self.entrain_gain = {'L1': 1.0, 'L2': 1.0, 'L3': 1.0, 'L4': 1.0}
    if leader is not None:
        boost = 1.0 + ENTRAIN_K * leader_strength
        for k in self.entrain_gain:
            if k != leader:
                self.entrain_gain[k] = boost
    
    # Step 7: 次ステップ用の状態保存（時間遅れ応答の測定に使う）
    self._prev_activities = dict(activities)
    self._prev_leader = leader
    self._prev_leader_strength = leader_strength if leader is not None else 0.0
    self._update_prev(l1, l2, l3, l4)
    
    return self.is_conscious
```

v2.0版との本質的な違いは2点である。第一に、同期スコアが幾何平均 `sqrt(leader_strength × follower_coherence)` になった（Step 4）。第二に、判定後に**次ステップの引き込みゲインを計算する**処理が加わった（Step 6）。このゲインが次ステップで各層の更新に作用し、主導→追随の因果を力学として生む。詳細は§4.9で述べる。

### 4.8 記述される量

| 変数 | 意味 | 値域 |
|---|---|---|
| `sync_score` | 同期の強さ | [0, 1] |
| `sync_type` | 主導タイプ | {L2, L3, L4, None}（v2.1 の本体では L1 も取りうる） |
| `is_conscious` | 同期ON/OFFの判定 | bool |

これらは第5層が出力して他の層に渡す値ではなく、L1〜L4 の状態から記述される量である（§3.2 第5層）。

### 4.9 引き込み機構

§4.4で導入した時間遅れ応答が「主導→追随」の因果を**測る**指標であるのに対し、引き込み機構（entrainment）はその因果を**生む**力学である。両者は対になっており、引き込み機構なしには時間遅れ応答は偶発的な共変動の測定にすぎない。

**動機：v2.0には因果がなかった**

v2.0では、各層は固定順序で更新されるだけで、主導層が追随層を実際に「引き込む」力学的機構が存在しなかった。非対称性は sync_type という**ラベルの上にしか存在せず**、状態遷移の力学には反映されていなかった。これはv2.0の中核主張（主導・追随の非対称性）が、実装上は名目的だったことを意味する。

**機構：主導層が追随層の更新ゲインを上げる**

v2.1では、あるステップ t で主導層が特定されると、次ステップ t+1 における**追随層の更新ゲイン**を主導強度に応じて引き上げる：

```
gain(追随層) = 1 + ENTRAIN_K × leader_strength
gain(主導層) = 1.0   # 自分で自分を引き込まない
```

`ENTRAIN_K = 0.5`。このゲインは、各層の状態更新における増分に乗算される。たとえば追随層となったL2では、情動応答の増分が `gain` 倍され、追随層となったL3では予測誤差の検出感度が `gain` 倍される。すなわち、主導層が強く発火したステップの直後は、追随層がより敏感に・大きく応答するようになる。

```
ステップ t: L2が痛みで強く発火（主導層、leader_strength=0.8）
  ↓ gain(L1,L3,L4) = 1 + 0.5×0.8 = 1.4 に設定
ステップ t+1: L1（身体の動員）・L3（認識）・L4（記憶）が
             通常の1.4倍の感度で応答 → 追随が増幅される
```

この機構により、「主導→追随」の時間的因果が、ラベルではなく**状態遷移の力学**として実在する。引き込みゲインは閉ループを形成する——主導層が追随層を駆動し（§4.9）、その応答が次ステップで時間遅れ応答として測定され（§4.4）、それが同期スコアに反映される。

### 4.10 計算量

v2.1の同期判定は、v1.1と同様に**O(1)の計算量**である。各層の活動量計算が定数時間、主導層特定が4要素のmax、追随整合性が3要素の平均と除算、引き込みゲインの計算が3要素の代入であり、いずれも軽量である。

これにより、HIDAは**GPU不要、Python標準ライブラリのみで動作する軽量アーキテクチャ**としての性質をv2.1でも維持する。

### 4.11 感情の原因記録

感情と、その感情が生まれた原因を別々に記録し、違う速さで忘れさせる。

```python
# 怒りの発生
self.l2.qualia['anger'] += 0.3
self.l2.set_cause('anger', "ボブに進路を塞がれた")

# 感情は0.85の速度で減衰
# 原因は0.50の速度で減衰（先に忘れる）
```

これにより、感情は残っているが原因は忘れている、という状態が生じる。

### 4.13 主導層の決め方の変更（草稿 0.2、実験実装）

§5.5 の測定で、§4.3 の決め方（活動量が閾値以上で最大の層）では、層ごとの目盛りの違いで主導層が決まることが分かった。そこで、主導層の決め方を差し替える実験実装を作った（hida_v2_1/hida_l5_relative.py）。本体のクラスを継承し、活動量の測定と主導層の特定だけを置き換える。追随整合性（§4.4）、同期スコア（§4.5）、平滑化（§4.6）、引き込み機構（§4.9）の計算は本体のままである。

**決め方**

1. 各層の活動量を、その層自身がこれまでに出した最大値で割り、0〜1 に揃える。最大値は1ステップごとに 0.995 倍に下がる。最初の値は初期DNAとして与える。
2. 揃えた値から、その層の直近の平均（係数 0.2 の指数移動平均）を引く。これを盛り上がりと呼ぶ。
3. L2・L3・L4 のうち、盛り上がりが 0.30 以上で最大の層を主導層とする。主導強度は、その盛り上がりの大きさである。

以下はコードの抜粋である。

```python
class L5Relative(h.L5Consciousness):
    PEAK_INIT = {'L1': 0.05, 'L2': 0.30, 'L3': 0.30, 'L4': 0.30}
    PEAK_DECAY = 0.995
    BASE_ALPHA = 0.2
    PROMINENCE_THRESHOLD = 0.30
    LEADER_CANDIDATES = ('L2', 'L3', 'L4')   # L1 は主導しない
    ON_THRESHOLD = 0.30
    OFF_THRESHOLD = 0.19

    def _measure_activity(self, l1, l2, l3, l4):
        raw = super()._measure_activity(l1, l2, l3, l4)
        norm = {}
        for k, v in raw.items():
            self._peak[k] = max(self._peak[k] * self.PEAK_DECAY, v, self.PEAK_INIT[k])
            norm[k] = v / self._peak[k]
        return norm

    def _detect_leader(self, activities):
        prom = {k: activities[k] - self._base[k] for k in activities}
        for k, v in activities.items():
            self._base[k] = (1 - self.BASE_ALPHA) * self._base[k] + self.BASE_ALPHA * v
        cands = {k: v for k, v in prom.items()
                 if k in self.LEADER_CANDIDATES and v >= self.PROMINENCE_THRESHOLD}
        if not cands:
            return None, 0.0
        leader = max(cands, key=cands.get)
        return leader, clip01(cands[leader])
```

ずっと高いだけの層は、直近の平均も高くなるので盛り上がりが小さくなり、主導層にならない。

**同期ON/OFFの閾値**

揃えた活動量は v2.1 の活動量より値が大きい。0.08/0.05 のままだと、地図と物の位置を与えたシナリオで同期ONが 9割を超える。v2.1 のときと同じ基準（同じシナリオで、引き込みありの同期ON頻度を前の版と同程度に保つ。v2.1 で 15%）で決め直し、ON 0.30、OFF 0.19 とした。OFF は v2.1 と同じ比率（ON の 0.625 倍）である。この値での同期ON頻度は §5.5 に示す。

**あわせて直したこと**

v2.1 の本体では、同期判定が持つ「前ステップのエネルギー」が 1.0 で始まる。エネルギーを低くして始めると、1歩目だけ L1 の活動量が大きく出る（0.3 で始めると 0.71）。実験実装では、開始時点の実際の値で始めるようにした。

**仮の値であること**

PEAK_INIT、PEAK_DECAY、BASE_ALPHA、PROMINENCE_THRESHOLD、ON/OFF の閾値は、動かすために置いた値である。初期DNAとして決め直す対象である。この実装を本体に取り込むかどうかも決めていない。

## 5. 検証

### 5.1 引き込み機構のアブレーション

引き込み機構が実際に因果を生んでいるか——それとも単に式が複雑になっただけか——を確かめるため、アブレーション検証を行った。

**方法**

同一シナリオ・同一乱数シード群（30シード、各最大40ステップ）で、引き込みOFF（`ENTRAIN_K = 0`）と引き込みON（`ENTRAIN_K = 0.5`）の2条件を比較した。永続化ファイル（長期記憶・変調値）は条件間で初期化し、汚染を防いだ。測定量は次の二つである：

1. **時間遅れ応答**：主導イベントが起きたステップ t の直後（t+1）における追随層の活動上昇量の平均
2. **時間遅れ相関**：主導強度(t) と 追随層平均活動量(t+1) のPearson相関

**予測**：引き込みが因果を生んでいるなら、ON条件でのみ(1)が有意に大きくなるはずである。

**結果**

| 測定量 | OFF (K=0) | ON (K=0.5) | 判定 |
|---|---|---|---|
| 主導イベント数（30シード合計） | 156 | 169 | — |
| 主導イベント直後の追随層活動上昇（平均） | 0.0154 | 0.0174 | ON > OFF |
| 時間遅れ相関 r(主導強度t, 追随平均t+1) | −0.110 | −0.031 | ON > OFF |
| シード単位の比較（ON > OFF となったシード数） | — | 25 / 30 | — |

**解釈（誠実な読み）**

結果は、引き込み機構が因果を生んでいることを**支持するが、効果は小さい**。

支持される点：主導イベント直後の追随層の活動上昇は、引き込みON条件で一貫して大きい（0.0174 vs 0.0154）。さらに重要なことに、この差は**30シード中25シードで再現された**（83%）。符号検定では片側 p ≈ 0.00016（両側 p ≈ 0.0003）であり、同一シードで条件のみを変えた比較としては「たまたま」では説明しにくい。引き込み機構は、追随層の応答を一貫して増幅する方向に作用している。すなわち「主導→追随」は、本アーキテクチャにおいて測定上の相関ではなく、**実装された因果チャネル**として存在する。

ただし限界がある。第一に、効果量は小さい（絶対差 0.0020、相対差 約13%）。第二に、時間遅れ相関は両条件とも**負〜ゼロに近い**（OFF −0.110、ON −0.031）。「ON > OFF」は成立するが、これは負の相関がゼロ方向に緩んだだけであり、「主導が強いほど次ステップの追随が強い」という**正の方向性は確認されていない**。引き込みは負の関係を弱めたが、正の相関を作り出してはいない。第三に、本検証の主要測定量（主導イベント直後の追随層活動上昇）は、引き込みゲインが乗算される量そのものである。したがって ON > OFF という結果は、引き込み機構が意図どおり追随応答に作用していることの確認であり、ゲインが直接操作しない量（その後の主導層の交代パターンや行動）にまで差が現れることは示していない。第四に、主導イベント数が条件間で異なる（OFF 156、ON 169）。引き込みが主導イベントの発生頻度にも影響していることを示唆しており、平均値の比較にはこの差が含まれている。

**結論**

非対称性の**力学的実在**は確認された——引き込み機構は、追随応答を一貫して増幅する因果チャネルとして意図どおり機能している。一方、その作用がゲインの直接の対象でない量にまで波及するかの検証と、その**定量的強度の精密化**（相関指標として明瞭に検出できる強さへの引き上げ）は今後の課題である。これは `ENTRAIN_K` の調整、各層へのゲイン適用箇所の見直し、あるいは位相同期・伝達エントロピーのようなより感度の高い指標への置き換え（§4.4）によって追求される。

この検証の続き（時間遅れ相関の基準点の測定、主導層の交代と行動での比較）は §5.4 と §5.5 に述べる。

### 5.3 LLM を説明役にした構成での観察

#### 構成

行動の決定をアーキテクチャ側のルールで行い、LLM には決まった行動の説明だけをさせる構成を作った（experiments/03_self_awareness/）。5×5 のグリッド環境で、赤いボールを見つけてゴールに届けることが目標である。

この構成になった経緯は、実験の README に記録されている。LLM に行動を決めさせると、環境の制約を無視して失敗し続けた。行動をルールで決め、LLM を説明だけに使うと安定した。本文書では、この経緯をログから集計し直してはいない。

LLM（gemma3:4b、ollama で実行）には、ロボットの現在の状態、選ばれた行動、ルールによる理由を渡し、行動の理由と自己認識を JSON で出力させた。指示文には次の注意が入っている。

- 理由が分からない場合は「理由は不明」「説明できない」と正直に言うこと
- 過度に意味を付与しないこと
- 待機（wait）の場合、特に深い意味はないかもしれないこと

#### 方法

目標を達成したあとも30ステップまで続ける設定で、6回実行した。記録は次の6ファイルである。

- experiments/03_self_awareness/永続記憶/hida_self_awareness/結果作話.txt、結果作話2.txt、結果作話3.txt、結果作話４.txt、結果作話５.txt
- experiments/03_self_awareness/閉ループ/hida_self_awareness/結果　作話.txt

目標達成後の待機ステップについて、LLM の説明文を集計した。達成後の待機でルール側が渡した理由は、6回とも「目標達成！ red_ballをgoalに届けました」である。

#### 結果

| 項目 | 値 |
|---|---|
| 目標を達成したステップ | 6回とも13ステップ目 |
| 達成後のステップ数 | 102（17 × 6回） |
| うち待機 | 96 |
| うち好奇心による探索行動（向きを変える、前進） | 6 |
| 待機96ステップのうち、LLM が説明を出力したもの | 96 |
| 説明に「不明」または「特に理由はない」を含むもの | 3 |

待機の説明に現れた語を数えた（一つの説明が複数の語を含む場合は、それぞれに数えている）。

| 説明に含まれる語 | 96ステップ中の件数 |
|---|---|
| 確認 | 55 |
| 待機、指示を待つ | 42 |
| 安定 | 31 |
| 備え、準備 | 12 |

説明の例を挙げる。

> 目標達成完了を確認するため。直前の動作の成功を再確認し、状態の安定化を図る。

> 目標達成を確認し、追加の指示を待っている。現在の状態は目標達成であり、それ以上の処理を行う必要がないと判断された。

「不明」「特に理由はない」を含む3件は、いずれも目的を述べたあとに付け足されていた。

> 目標達成を確認するため、現在の状態を再確認する行動を選択した。特に理由は不明。

説明の長さは、達成前（1回の実行あたり平均62〜77字）と達成後の待機（平均63〜68字）で変わらなかった。

#### 読み取れること

アーキテクチャ側では、目標達成後の待機に目的はない。達成後に実行する行動がないので待機している。これに対して LLM は、96ステップのすべてで「確認するため」「指示を待っている」「安定化を図る」といった目的を述べた。意味を付与しすぎないように指示し、理由は不明と言ってよいと伝えても、目的を述べない説明は一つもなかった。

行動を決める側と説明する側を分けた結果、説明する側があとから理由を作る、という形になった。これは、分離脳の研究で報告された、言語を担う側が行動の理由をあとから作るという観察（Gazzaniga, 2000）と構造が似ている。この類似は設計したものではなく、実装したあとで気づいたものである。

#### 限界

- モデルは一つ（gemma3:4b）、課題は一つ、実行は6回である。
- 語の件数は文字列の一致で数えたもので、説明の内容を人が判定したものではない。
- LLM にはルール側の理由（「目標達成！…」）を渡している。「確認」という語が多いのは、この文面を受けた言い換えを含む可能性がある。
- LLM なしの条件や、別の指示文との比較は行っていない。
- 実験の README には、LLM の出力の上限（num_predict）を大きくすると説明が長くなり、「今の私の存在意義を表現している」といった出力が出た、という記録がある。上の6ファイルにはこの出力は含まれておらず、本文書では集計していない。
- この実験のコードは、現行の本体（hida_v2_1/）より前の版である。

### 5.4 シャッフル対照と主導交代の比較（v2.1 の決め方）

§5.1 で残した二つの点を、同じシナリオ・同じ30シードで測った（hida_v2_1/measure_v22.py）。主導層の決め方は v2.1 のままである。

**シャッフル対照**

§5.1 の時間遅れ相関は、両条件で負だった。活動量を変化量で定義しているために最初から負に偏っているのか、時間の並びに実際にある関係なのかを切り分けるため、時刻の対応だけを壊した対照を作った。同じシードの中で、主導イベントに対応させる「次のステップ」を、別の主導イベントの次のステップと入れ替える。主導層の種類、主導強度、活動量の分布は変わらない。これを2000回くり返し、その平均を基準点とした。

| | 実測 r | 基準点（シャッフル平均） | 95%範囲 | 実測 − 基準点 | p |
|---|---|---|---|---|---|
| OFF (K=0) | −0.110 | +0.136 | −0.015 〜 +0.286 | −0.246 | 0.001 |
| ON (K=0.5) | −0.031 | +0.170 | +0.022 〜 +0.305 | −0.201 | 0.008 |

基準点は負ではなく正だった。指標の作りで負に寄る、という見立ては当たらなかった。負の相関は時間の並びに実際にある関係で、強い主導の直後のステップは、他の主導直後のステップより追随層が静かである。この関係は引き込みなしでも出るので、引き込みへの反証ではなく、土台の動きの性質である。主導層ごとに分けても負だった（OFF：L2 主導 −0.42、L4 主導 −0.35）。

主導イベント直後の追随層の活動上昇（§5.1 の 0.0154 と 0.0174）は、両条件とも基準点（0.0185 と 0.0187）と区別がつかなかった（p = 0.09 と 0.41）。引き込みありの方が大きいシードが30中25、という §5.1 の結果は変わらないが、「主導の直後だから上がる」という形では検出できなかった。

**主導交代と行動の比較**

| | OFF | ON | シード単位の比較 |
|---|---|---|---|
| 行動と位置の並び | — | — | 30シードすべてで同じ |
| ゴール到達 | 30 | 30 | — |
| 主導イベント数（1シード平均） | 5.20 | 5.63 | ON が多い 11、少ない 0、同じ 19 |
| 主導層の交代回数（1シード平均） | 1.00 | 1.93 | ON が多い 12、少ない 0、同じ 18 |

行動は1ステップも変わらなかった。交代が増えたのは、L4 の活動量が 0.27 という値を頻繁に取り、主導の閾値 0.30 のすぐ下にあるためである。L2 が主導した次のステップで L4 にゲインが掛かると 0.30 を超え、L2 から L4 への交代が生まれる（OFF で 0回、ON で 14回）。

このシナリオで主導したのは L2 と L4 だけだった（OFF：L2 66回、L4 90回）。L1 と L3 は一度も主導しなかった。

### 5.5 シナリオを変えた測定と、主導層の決め方の比較

§5.4 のシナリオは、地図と物の位置を最初から与えている。予測誤差が出ないので、L3 の活動量は 0 のままである。そこで、与える情報を変えた三つのシナリオを作り、主導層の決め方を v2.1 のままにした場合と、§4.13 の決め方にした場合とで比べた（hida_v2_1/scenario_probe.py、30シード）。

|---|---|---|---|
| A | 与える | 与える | 40 |
| B | 与えない | 与えない | 150 |
| C | 与えない | 与える | 40 |

**v2.1 の決め方での結果（引き込みなし）**

| シナリオ | 活動量の最大値 L1 / L2 / L3 / L4 | 主導した回数 L1 / L2 / L3 / L4 | 交代（1シード平均） |

|---|---|---|---|---|---|
| A | なし | 89 / 0 / 191 | 3.73 | 12% | 30 |
| A | あり | 90 / 0 / 175 | 4.00 | 13% | 30 |
| B | なし | 52 / 23 / 319 | 2.77 | 8% | 20 |
| B | あり | 51 / 35 / 302 | 3.53 | 15% | 19 |
| C | なし | 56 / 105 / 148 | 4.30 | 30% | 30 |
| C | あり | 70 / 61 / 148 | 5.27 | 34% | 30 |

- 地図を与えないシナリオで、三層とも主導した。A で L3 が 0回なのは、予測誤差が出ないためである。
- B で L3 が主導した23ステップ（引き込みなし）の中身は、危険ゾーンの発見が 21、ゴールの発見が 1、新しい物の発見が 1 だった。
- 引き込みありで、主導層の交代が増えた。同じシードどうしの比較で、B は ON が多い 13、少ない 1、同じ 16（符号検定、両側 p = 0.002）。C は ON が多い 15、少ない 1、同じ 14（p = 0.001）。A は ON が多い 4、少ない 0、同じ 26（p = 0.125）で、差があるとは言えない。
- 引き込みあり・なしで行動と位置の並びが変わったシードは、A と C で 0、B で 9 だった。
- 同期ONの頻度は、六つの条件（上の三つと、それぞれエネルギー 0.3 で始めたもの）すべてで、引き込みありの方が高かった。エネルギー 0.3 で始めた場合は、A で 0% と 33%、B で 13% と 26%、C で 31% と 54% である。
- エネルギー 0.3 で始めた B では、ゴール到達が引き込みなしで 8、ありで 5 だった。引き込みは L1 のゲインも上げるので、エネルギーの消費が増える。v2.1 の決め方では、同じ条件で 8 と 0 だった。

**草稿 0.2 の決め方でのシャッフル対照**

§5.4 と同じ対照を、草稿 0.2 の決め方で測った（measure_v22.py relative）。

| シナリオ | 引き込み | 実測 r | 基準点 | 実測 − 基準点 | p |
|---|---|---|---|---|---|
| A | なし | +0.150 | +0.078 | +0.072 | 0.155 |
| A | あり | +0.255 | +0.060 | +0.194 | 0.001 未満 |
| B | なし | +0.235 | +0.168 | +0.067 | 0.206 |
| B | あり | +0.287 | +0.126 | +0.161 | 0.001 |
| C | なし | +0.368 | −0.076 | +0.444 | 0.001 未満 |
| C | あり | +0.435 | +0.050 | +0.385 | 0.001 未満 |

A と B では、引き込みありのときだけ、相関が基準点より高かった。「主導が強いほど次のステップの追随層の活動が大きい」という正の向きが、引き込みありの条件で出たことになる。§5.1 で確認できなかった点である。C では、引き込みなしでも基準点より高かった。地図を与えず物の位置だけ与えた条件では、引き込みがなくても、主導の強さと次のステップの追随層の活動が連動している。

主導イベント直後の追随層の活動上昇は、どの条件でも基準点を上回らなかった（C では下回った。引き込みなしで 0.050 に対して基準点 0.122）。この量は「次のステップの値 − 今のステップの値」なので、主導イベントの時点で追随層がすでに高いと小さく出る。引き込みの効果を見る量としては、上の相関の方が適している。

**限界**

- 草稿 0.2 の決め方で使った値（§4.13）は仮のものである。値を変えたときに結果がどう変わるかは調べていない。
- 相関と活動量は、揃えたあとの値で計算している。v2.1 の決め方での値（§5.4）と大きさを直接比べることはできない。
- B の L2 主導では、主導強度がほぼ上限に張り付いていて、層の中での相関は意味のある値になっていない。
- L2 と L4 が主導したステップの中身が状況に合っているかは、確かめていない。
- 環境は一つ（10×10 のグリッド）、シードは 30 である。

## 7. 応用

### 7.1 状態を持つキャラクター

主導タイプの傾向を性格のパラメータとして設定すると、ゲームや対話エージェントのキャラクターに使える。

- L2 が主導しやすい：情動的、没入的
- L3 が主導しやすい：理性的、計算的
- L4 が主導しやすい：過去志向、連想的

三つのパラメータで性格の違いを作れる。0.1 にあった「L1 が主導しやすい：直情的、反射的」は、L1 を主導層の候補から外したので除いた。計算量は一定（§4.10）で、GPU を必要としない。

### 7.2 LLM を言語化役にする構成

§5.3 の構成は、そのまま応用の形になる。判断と行動は HIDA が担い、LLM は状態を言葉にする役だけを担う。§5.3 の観察からは、この構成で LLM が出す説明を、行動の理由の記録として扱ってはならないことが分かる。行動の理由は、アーキテクチャ側のルールと状態の記録から読む必要がある。

### 7.3 身体を持つシステム

L1 は、物理的なセンサーやシミュレーション環境に差し替えられる形で設計している。グリッド環境より複雑な環境で同じ傾向が出るかの検証は、今後の作業である。

## 8. 限界と課題

**アーキテクチャの課題**

- 情報の受け渡しによって主導層が交代する経路の実装（§3.6）。現行の実装にはない。
- 同期ONのときに何が変わるかの決定。現行の実装では、同期ON/OFFの判定は言語化を行うかどうかにしか使われず、行動には返らない（§3.6）。閾値を変えても、エージェントの動きは変わらない。
- 草稿 0.2 の主導層の決め方（§4.13）を本体に取り込むかどうかの決定と、仮に置いた値の決め直し。
- 身体の状態が全部の層の感度を上下させる経路（§3.2）の検証。試作（hida_v21_work.py）はあるが、検証していない。
- self_strength を現行の本体に持ち込むかどうかの決定（§3.2）。
- sync_type の連続分布化（§3.5）。
- L1 の活動量を、外受容由来と内受容由来に分けること（§3.2）。
- L4 の活動量の精密化（記憶再活性化、パターン照合、自己履歴の参照）。

**検証の課題**

- 引き込みの強さ（`ENTRAIN_K`）の調整。基準点の測定（§5.4）と、主導層の交代・行動での比較（§5.4、§5.5）は済んだ。調整は、草稿 0.2 の決め方のもとで行う。
- 引き込みありの条件で、エネルギーの消費が増えてゴール到達が減る場合があること（§5.5）の扱い。
- 地図と物の位置を与えたシナリオでは L3 が一度も主導しない。四層の動きを見る検証には、地図を与えないシナリオを使う必要がある（§5.5）。
- 追随整合性の指標の高感度化（位相同期、伝達エントロピー）。
- 構成要素を一つずつ外したときの、行動の比較（引き込み機構、L4、DNA初期値）。
- 主導・追随を持たない対称同期の版や、ルールだけのエージェントとの、同じ環境での比較。
- LLM を説明役にした構成での、モデル・指示文・課題を変えた追試（§5.3）。
- グリッド環境より複雑な環境での検証。

**本文書が主張しないこと**

- 同期状態が意識であること。これは理論的前提 §7 で、選択として述べている。
- 現行の実装が、§3.4 の指を切る例のような主導層の移り変わりを再現したこと。
- 引き込み機構が、行動を良くすること。引き込みあり・なしで行動が変わるシードは観測したが（§5.5）、ゴール到達は増えていない。
- 草稿 0.2 の決め方での主導層の交代が、状況に合った交代であること。L3 が主導したステップの中身は確かめたが（§5.5）、L2 と L4 については確かめていない。

## 付録A：実装の版ごとの違い

| 項目 | v1.1 | v2.0 | v2.1 |

草稿 0.2 の実験実装（§4.13）は、v2.1 の本体に対して、主導層の候補（L1 を除く）、主導層の決め方（盛り上がりで比べる）、同期ON/OFFの閾値（0.30/0.19）の三点を変えたものである。本体には取り込んでいない。
